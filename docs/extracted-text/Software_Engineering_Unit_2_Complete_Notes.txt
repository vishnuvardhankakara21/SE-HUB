Cohesion\nDefinition\nCohesion is the degree to which the elements within a module are related to one another and contribute to a\ncommon purpose. High cohesion is desirable because it makes a module easier to understand, test, and\nmaintain.\nTypes of Cohesion\nThe following types are generally arranged from weakest to strongest.\n1. Example: A module handles different types of input operations, such as\nkeyboard input and file input.\n3. Temporal Cohesion: Tasks are grouped because they occur at the same time. Example: A startup module\nloads configuration, opens log files, and initializes connections.\n4. Procedural Cohesion: Tasks are grouped because they must follow a particular sequence, even though they\nmay operate on different data. Example: A module validates an input, records an event, and displays a message in\na required order.\n5. Communicational Cohesion: Tasks are grouped because they operate on the same data. Example: A module\nretrieves a student's record and calculates a result using that record.\n6. Sequential Cohesion: The output of one task becomes the input of the next task within the same module.\nExample: A module reads marks, calculates the total, and then calculates the percentage.\n7. Functional Cohesion: All elements of a module contribute to one well-defined function. Example: A module\nperforms only the calculation of a student's final grade.
